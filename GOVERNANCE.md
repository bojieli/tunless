# Governance

Tunless is maintainer-led. The maintainer sets project scope, reviews and merges
changes, manages security advisories, and decides when documented release gates
have passed. Technical decisions favor observable correctness, a small trusted
computing base, fail-open cleanup, compatibility with unmodified applications,
and measurements on real target platforms.

Substantial decisions should be recorded in pull requests or design documents
so later contributors can understand the evidence and tradeoffs. Compatibility
claims require tests; popularity alone does not make a platform supported.

New maintainers may be invited after sustained high-quality contributions,
sound security judgment, and reliable review participation. A maintainer may
step down at any time. If the project becomes inactive, the maintainer should
identify a successor or clearly mark the repository unmaintained.
